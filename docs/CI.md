# CI and repository scanning

Install RenderDiff in an isolated environment and run `renderdiff-scan --format sarif --output renderdiff.sarif --fail-on-material path/to/file`. The command exits 2 for material/potentially-material findings and never edits scanned files. A single-file CLI also supports JSON, HTML, SARIF and PDF exports. The included local pre-commit configuration is opt-in. `action.yml` is a reusable composite action, not an automatically triggered workflow; the repository does not enable GitHub Actions.

Only regular explicitly supplied files are scanned. There is no recursive arbitrary-repository execution, no untrusted build step, and no implicit network fetching. Repository-wide scanning should enumerate files with an explicit allowlist and size budget, excluding secrets, generated assets, dependency trees and binary formats not supported by the extractor. The calling CI system owns failure policy, authentication and artifact retention. Do not publish evidence reports containing private material to public logs or artifacts.
