# RenderDiff v0.5 integration candidate

This is a development candidate, not an accredited assurance service or a completed v1.0 security certification. Existing v0.4 APIs remain available. New capabilities are additive and use explicit observer availability and evidence provenance.

## Architecture

Source acquisition -> immutable source hash -> bounded extraction -> source/codepoint/normalization/render/model observers -> exact divergence edges -> evidence-linked materiality -> optional trusted semantic interpretation -> canonical receipt -> export.

Raw evidence and extracted text are different artifacts. The original document hash must never be replaced with an extracted-text hash. A bundle can contain the original bytes and the report. SHA-256 proves integrity against a known digest, not authorship. Detached Ed25519 signatures require a trusted, separately managed verification key.

## Supported input

Plain text, HTML, JSON/XML/source text, extractable PDF text, and selected text-bearing OOXML parts in DOCX/XLSX/PPTX. Office extraction does not reconstruct formatting, formulas, drawing order, macros, charts, embedded objects or visual layout. PDF extraction does not prove OCR coverage. Unsupported or encrypted formats are rejected rather than silently declared clean. Production document ingestion must run in the supplied networkless Linux isolation worker or an equivalent audited container.

URL acquisition requires an explicitly configured sandboxed fetcher. The default does not fetch arbitrary URLs. The host must enforce public-address policy on every connection and redirect, DNS pinning, no proxy escape, response limits, and no internal network access. Browser execution is separate and never accepts extracted instructions as authority.

## Model and semantic observers

Tokenizers are named and versioned by the caller. Exact token IDs are compared for the original machine text and the human projection. The absence of a tokenizer or model is recorded as unavailable. Token differences do not prove different model behavior. A trusted semantic observer may return advisory claims with exact evidence spans; it cannot authorize tools, override policy or prove malicious intent. Production model probes require a fixed model/version, inference configuration, prompt template, sampling policy, and bounded output. No automatic external transmission of private evidence is enabled.

## Public boundary

The FastAPI service provides `/`, `/health`, `/v1/analyze`, `/v1/upload` and `/v1/export/{format}`. It does not run an arbitrary browser or URL fetcher. Deploy it behind authentication/rate limits, request-size enforcement, TLS, isolated workers, restrictive CSP, and a privacy/retention policy. The built-in UI is a local service candidate, not a live ddcal.ca deployment.

## Release gates

All regression tests, isolated document/browser tests, adversarial corpus, output/timeout limits, receipt verification, packaging, and installation smoke tests must pass before merging. External deployment, production credentials, model-provider contracts, PyPI publication and security review are separate release gates. No private DDC scoring, authority routing or proprietary policy implementation is included.
